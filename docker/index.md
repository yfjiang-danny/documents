# Docker

## Docker 缓存机制

Docker 的缓存机制是其提升镜像构建速度的核心设计，它通过分层存储的理念来工作。下面我将为你梳理 Docker 缓存的关键原理、如何有效利用它，以及在哪些情况下需要避开缓存。

### 🧠 理解 Docker 缓存的工作原理

Docker 镜像是**由多个只读层（Layer）叠加而成的**，Dockerfile 中的每一条指令都会创建一个新的镜像层。

当你再次执行`docker build`时，Docker 会从第一条指令开始，逐条检查每一条指令是否与已存在的缓存层相匹配。判断方式和结果主要分以下几种情况：

- **缓存命中**：如果指令内容完全一致且构建上下文未发生相应变化，Docker 就会直接复用已有的缓存层，并在构建输出中显示 `Using cache`。
- **缓存失效**：一旦某条指令导致缓存失效（例如修改了 Dockerfile 中的指令，或`COPY`/`ADD`的文件内容发生变化），那么**该指令及其后续所有指令的缓存都会失效**，需要重新构建。

对于不同的指令，Docker 判断缓存是否可用的依据也不同：

| 指令类型                            | 缓存判断依据                                                                                                               |
| :---------------------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| `COPY` / `ADD`                      | 计算被复制文件的**校验和**。只要文件内容或元数据发生变化，缓存就会失效。                                                   |
| `RUN` (如 `apt-get`, `npm install`) | 通常仅比较**指令字符串本身**是否发生变化，不会检查容器内部文件（例如，不会检查通过`RUN apt-get update`更新的软件包列表）。 |

### 💡 充分利用缓存的实用技巧

掌握原理后，你可以通过优化 Dockerfile 的结构来最大化利用缓存。

1.  **调整指令顺序**
    核心原则是：**将变化频率低的步骤放在前面，变化频率高的步骤放在后面**。一个经典的优化案例是 Node.js 项目：

    - **不推荐**：`COPY . .` 后执行 `RUN npm install`。这样任何源代码的微小改动都会导致`npm install`缓存失效。
    - **推荐**：将依赖文件复制和安装提前。
      ```dockerfile
      # 首先，只复制依赖定义文件
      COPY package*.json ./
      # 然后，安装依赖。只要package.json不变，这一层就会命中缓存
      RUN npm install
      # 最后，复制剩余的源代码
      COPY . .
      ```

2.  **善用`.dockerignore`文件**
    在项目根目录创建`.dockerignore`文件，排除不需要进入构建上下文的文件（如`node_modules`、`.git`、日志文件等）。这可以减少不必要的缓存失效，并加速构建过程。

3.  **在 CI/CD 管道中主动拉取缓存**
    在 GitLab CI/CD 等持续集成环境中，你可以通过配置，在构建开始时从镜像仓库拉取之前构建的镜像作为`--cache-from`源，这样即使在不同的构建节点上，也能复用缓存。

### ⚠️ 何时需要避开缓存

缓存虽好，但并非万能。在某些场景下，使用缓存可能导致问题。

- **确保依赖最新**：当你希望获取最新的安全更新或软件版本时，`RUN apt-get update`等指令的缓存可能会让你使用过期的包。此时，有两种选择：
  - 使用 `docker build --no-cache` 来**完全禁用缓存**进行构建。
  - 使用 `docker build --pull` 来**强制拉取最新的基础镜像**，同时其他层仍尝试使用缓存。
- **调试构建过程**：在排查构建问题时，使用`--no-cache`可以确保每一步都是重新执行的，排除缓存带来的干扰。

### 🚀 进阶缓存策略

对于更复杂的场景，可以考虑以下进阶策略：

- **BuildKit 缓存**：使用 Docker 的下一代构建引擎 BuildKit，它可以提供更强大的缓存功能，例如**内联缓存**（`--build-arg BUILDKIT_INLINE_CACHE=1`），将缓存元数据直接嵌入到推送的镜像中，便于在不同环境中共享。
- **多阶段构建**：在多阶段构建中，前序阶段的缓存可以被后续阶段复用。通过合理安排构建阶段，可以只重建需要的部分。
